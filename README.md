# Mini DAW 2.1.0

Редактор многодорожечного аудио для Windows и браузера: монтаж клипов, эффекты, сохранение проекта вместе с исходниками, экспорт WAV/MP3. Основа — React, TypeScript, Vite, Zustand, Web Audio API и Electron. В репозитории сохранена Android-оболочка Capacitor.

Описание изменений находится в [заметках к версии](docs/RELEASE_NOTES_2.1.0_RU.md), дальнейшая работа — в [backlog](docs/BACKLOG_RU.md). Фактические результаты прогонов, путь проверенного EXE и контрольные суммы фиксируются отдельно в [отчёте проверки](docs/VERIFICATION_2.1.0_RU.md). Наличие команды сборки или старого EXE само по себе не подтверждает готовность новой версии.

## Запуск и проверки

Используйте Node.js **24.15.0** из `.nvmrc`; `package.json` разрешает ветку Node 24 начиная с этой версии. Команды выполняются из корня проекта:

```sh
npm ci
npm run dev
```

Веб-редактор доступен по `http://127.0.0.1:5173`. Для запуска desktop из исходников:

```sh
npm run start
```

`start` собирает production-версию и запускает Electron. `npm run electron:dev` запускает Electron вместе с сервером Vite для разработки. Сервер привязан к loopback; разрешение любых Host отключено.

```sh
npm run check
npm run test:ui
npm run portable
npm run test:desktop
npm run release:manifest
```

- `check` последовательно выполняет ESLint, Node-тесты модели/аудио/сохранения и TypeScript/Vite build.
- `test:ui` запускает Playwright и сам поднимает dev server. На Windows конфигурация использует установленный Microsoft Edge; на Linux нужен Chromium: `npx playwright install --with-deps chromium`.
- `portable` собирает Windows portable. Файл: `release/2.1.0/Mini-DAW-2.1.0-portable.exe`. Каждая упаковка использует новую `release/2.1.0/build-<timestamp>` и лишь после успеха заменяет EXE; это обходит блокировки повторного `win-unpacked` в Windows. Связь сборки и файла записана в `packaging.json`.
- `test:desktop` требует уже собранный EXE. Он копирует его в новую папку `test-results/portable-smoke-*`, использует отдельный профиль и проверяет запуск, импорт, сохранение, перезапуск и экспорт. Рабочий пользовательский профиль для этого не нужен.
- `release:manifest` проверяет соответствие JS/CSS внутри упаковки текущему build, сохраняет SHA-256, размер, версии и фактический статус подписи Windows. Тестовый драйвер portable подключается к локальным отладочным портам только при smoke-запуске; обычный запуск их не открывает.

Для отдельных проверок доступны `npm test`, `npm run lint`, `npm run build`. Workflow `.github/workflows/check.yml` описывает PR-проверки редактора и Windows-сборки. Факт их прохождения нужно сверять с журналом конкретного запуска.

## Сохранение и пользовательские данные

**Новый / Открыть / Сохранить / Сохранить как** находятся в верхней панели. Рядом показаны имя проекта, несохранённые изменения и состояние восстановления. Файл `.mdaw` содержит версионированный документ и исходные байты всех импортированных медиа; его можно перенести на другой компьютер без исходных WAV/MP3 рядом.

В Electron повторное сохранение обновляет выбранный файл через временный файл и атомарное переименование в той же папке. Предыдущее содержимое хранится в `<имя>.mdaw.bak`; первая запись нового проекта резервной копии ещё не имеет. Desktop-мост ограничивает размер проекта 1 GiB. В браузере сохранение скачивает `.mdaw`; открытие выполняется через выбор файла.

Автовосстановление хранит текущую и предыдущую копию документа вместе с медиа в IndexedDB. Загрузка восстановления завершается до включения autosave. Ошибки чтения/записи и отсутствующее аудио видны в интерфейсе; для медиа предусмотрено повторное связывание. Старый JSON без аудио не может восстановить потерянные исходники автоматически. Для relink требуется совпадающая длительность файла. Полезно сохранять отдельный `.mdaw`: очистка данных браузера/профиля удаляет локальное восстановление.

Portable хранит профиль в **`Mini DAW Data` рядом с запущенным EXE**. Если новый EXE находится в `release/2.1.0`, его профиль будет `release/2.1.0/Mini DAW Data`. Существующий `release/Mini DAW Data` относится к прежнему расположению portable и сохраняется. Перенос проекта между ними выполняйте через `.mdaw`, а не очисткой или заменой профиля.

Настройки языка, панелей, избранного, недавних и пользовательских цепочек сохраняются локально. История Undo хранит только монтажные данные без копий PCM/peaks; она действует в текущем сеансе. Импорт остаётся в библиотеке при отмене других действий и сбрасывает Redo. Медиа, на которые ссылаются проект, clipboard или история, нельзя удалить из реестра преждевременно.

## Монтаж и навигация

- Заголовки дорожек остаются слева при горизонтальном скролле. В них доступны имя, цвет, Mute/Solo, громкость и действия дорожки; дорожки можно искать, переставлять, дублировать, удалять и менять их высоту.
- Колесо прокручивает дорожки, Shift+колесо — время. Средняя кнопка панорамирует. Ctrl/Cmd+колесо меняет масштаб вокруг указателя; двухосевые жесты trackpad сохраняют нативную прокрутку.
- Нижний обзор позволяет двигать видимую область и менять её ширину. Есть переход к началу/концу/курсору, ввод времени, Follow и команды вписать проект, выделение или клип. Ручная прокрутка временно приостанавливает Follow.
- Привязка включается явно: секунды или доли с редактируемым BPM. Alt временно её отключает. Shift+перетаскивание по линейке задаёт петлю.
- Ctrl/Cmd и Shift дополняют выделение; рамка выделяет группу. Для клипов доступны перемещение между дорожками, trim, копирование, вставка, дублирование, split, nudging и fades. Esc отменяет незавершённый жест; Undo отменяет один завершённый жест.

Пересекающиеся клипы **суммируются**. Fade in/out — линейные огибающие амплитуды в секундах таймлайна. Команда crossfade задаёт парные fades на перекрытии выбранных последовательных клипов одной дорожки; исходные файлы не меняются. Если клип растянут за конец источника, хвост обозначается как тишина.

Клавиатура вне полей ввода и диалогов:

- Space — Play/Pause; Home/End — курсор к началу/концу; F / Shift+F — вписать проект/выделение.
- Ctrl/Cmd+S — сохранить; Ctrl/Cmd+Shift+S — сохранить как; Ctrl/Cmd+O — открыть; Ctrl/Cmd+N — новый проект.
- Ctrl/Cmd+Z — Undo; Ctrl/Cmd+Shift+Z или Ctrl/Cmd+Y — Redo.
- Ctrl/Cmd+A/C/V/D — выделить всё / копировать / вставить / дублировать клипы.
- Delete/Backspace — удалить выбранные клипы; S — разрезать их в позиции курсора.
- Стрелки ←/→ — сдвиг 0,01 с; Shift+стрелка — 1 с. Esc — отменить жест.

## Звук и экспорт

Скорость и полутона управляют **ресэмплингом**: высота и длительность связаны. Это не независимые time-stretch/pitch-shift. Изменение скорости дорожки сохраняет выбранный отрезок исходника, меняя длительность клипа; offset хранится в секундах источника. Live и offline используют общие преобразования времени и огибающие клипов. Без loop воспроизведение завершается через 2 с после конца материала; для более длинного хвоста FX задайте нужное время в экспорте.

Обход всей цепочки сохраняет индивидуальные BYP. Два набора параметров A/B не поддерживаются. Отдельные L/R sample peak/RMS, clip hold и корреляция помогают контролировать сигнал; они не являются измерителями integrated LUFS или true peak.

Экспорт предлагает WAV PCM 16/24 bit и MP3 128–320 kbit/s, 44,1/48 kHz, весь материал, loop, произвольное время или временной диапазон выделенных клипов. Последний вариант рендерит **микс в выбранном диапазоне**, а не только выбранные клипы. Хвост FX задаётся явно от 0 до 60 с. Для stems отдельно выбираются учёт Mute/Solo и применение мастера. Очередь хранит настройки и снимок каждого задания; имена файлов поддерживают кириллицу.

Нормализация работает по sample peak. Loudness normalization, true-peak limiting и dither не заявлены. «Параметрический EQ (статический)», «Сэмпловый экспандер», «Тембровый корректор», «Очищающие фильтры» и «Пиковый компрессор» описывают фактические упрощённые алгоритмы. Для полноценного динамического EQ, envelope gate, transient detection и шумоподавления нужна отдельная DSP-работа.

Peaks, анализ, нормализация и кодирование вынесены в Worker. Отмена native OfflineAudioContext отбрасывает результат и предотвращает запись файла, но не гарантирует немедленной остановки вычисления внутри браузера. Большие проекты требуют памяти для декодированного PCM; лимит `.mdaw` не гарантирует, что любой файл такого размера поместится в память.

## Карта проекта

- `src/App.tsx` — общий интерфейс, файловые команды, диспетчер клавиатуры, панели и статусы.
- `src/components/` — таймлайн, транспорт, библиотека, инспектор, FX, измерители, диалоги и ErrorBoundary.
- `src/state/model.ts`, `store.ts` — инварианты документа, команды монтажа, selection, транзакции и Undo/Redo.
- `src/state/persist.ts`, `session.ts`, `mediaRegistry.ts` — схема и контейнер `.mdaw`, IndexedDB, восстановление, файлы и реестр исходных Blob.
- `src/audio/` — runtime AudioBuffers, scheduler, общая модель времени, граф FX, offline render, измерение и Worker.
- `src/i18n/` — русские/английские сообщения и сохранение языка; `src/utils/` — время, ID и допустимые имена файлов.
- `electron/` — изолированный preload-мост, файловые диалоги, атомарная запись и ограничения desktop-окна.
- `tests/` — Node-регрессии; `tests/ui/` — Playwright-сценарии UI и настоящего Web Audio; `scripts/desktop-smoke.mjs` — проверка собранного portable.
- `scripts/generate-icon.mjs`, `src/assets/app-icon.svg`, `build/` — генератор и ресурсы иконок. `build/` не является папкой для безусловной очистки.
- `android/`, `capacitor.config.ts` — Android-оболочка. `npm run android:sync` обновляет web assets, `npm run android:open` открывает Android Studio; эти команды не подтверждают device-проверку.
- `dist/` — результат web build; `release/2.1.0/` — выход упаковки; `test-results/` — новые логи, снимки и изолированные тестовые профили.
- `docs/` — исходный аудит, техническое задание, изменения, проверка и backlog; `.github/workflows/` — конфигурация CI.

## Порядок в рабочей папке

Предыдущий `release/Mini-DAW-1.2.0-portable.exe` и профиль `release/Mini DAW Data` сохраняются. Старый соседний архив `../mini-daw-archive-2026-09-26` с `cleanup-manifest.json` и SHA-256 не восстанавливается и не очищается новой сборкой.

После проверки ссылок и генератора удалены только четыре неиспользуемых ресурса: `src/assets/hero.png`, `src/assets/react.svg`, `src/assets/vite.svg`, `public/icons.svg`. Исходные медиа, Android, иконки `build/`, lockfile и пользовательские правки не относятся к мусору. Не удаляйте всю `release`: внутри находятся данные portable.

Упаковщик использует runtime из пакета Electron (при первом запуске пакет сам загружает закреплённую версию). Завершённый `build-*`, указанный в `packaging.json`, нужен для повторной проверки manifest, но для запуска достаточно верхнего portable EXE. Старые `build-*` и `test-results*` — созданные проверками файлы; очищайте только явно выбранные каталоги после остановки их процессов, исключая пользовательские профили. Успешная сборка не удаляет старые каталоги автоматически.

Проверка реального звукового выхода и Android на устройстве/эмуляторе требует отдельного отчёта. Unit/mock-тесты, browser OfflineAudioContext и запуск EXE дают разные уровни доказательства и не заменяют аппаратное прослушивание.
