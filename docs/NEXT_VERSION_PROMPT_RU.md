# Промпт для разработки следующей версии Mini DAW

Ты работаешь в существующем проекте Mini DAW: React, TypeScript, Vite, Zustand, Web Audio API, Electron; есть Android-оболочка Capacitor. Нужно реализовать следующую стабильную версию с удобным монтажом, навигацией по дорожкам и более понятным интерфейсом.

Это задача на изменение работающей программы до проверяемого результата. Не ограничивайся планом, макетом, новой цветовой темой или описанием возможностей. Используй текущий код как основу, исправь подтверждённые дефекты и собери рабочий Windows portable.

Сначала прочитай `docs/AUDIT_RU_2026-09-26.md`, изучи текущее состояние репозитория и перепроверь относящиеся к работе findings: после аудита код мог измениться. Файл аудита содержит доказательства, номера строк, ограничения проверок и подробные предложения. Ниже — самостоятельное техническое задание.

## Приоритет результата

Сначала сохранность проекта и корректность звука/Undo, затем навигация и читаемость UI, затем новые монтажные возможности. Любая показанная как доступная функция должна действительно работать. Для сложного неподдерживаемого DSP честно сократи интерфейс либо реализуй и проверь алгоритм.

Основная платформа — Windows desktop. Сохрани возможность работы веб-версии. Android не удаляй; не объявляй его проверенным без сборки и проверки на устройстве/эмуляторе. Полный touch-редизайн и новые сложные DSP-функции не должны блокировать стабильную desktop-версию.

## Сохранить существующую работу и порядок в папке

- Перед изменениями проверь Git: при аудите имелось много пользовательских staged/unstaged/untracked изменений. Не отменяй, не затирай и не включай чужие изменения в свои коммиты без разбора.
- Сохрани исходники, медиа и пользовательские данные. Не выполняй очистку всей release: `release/Mini DAW Data` — профиль portable-приложения.
- В рамках аудита старые версии, win-unpacked, старые QA-снимки и логи уже перемещены в соседнюю `mini-daw-archive-2026-09-26`. Там есть cleanup-manifest.json и SHA-256. Не восстанавливай старые артефакты в рабочую папку без необходимости.
- В release оставлены portable 1.2.0 и пользовательский профиль; наличие старого EXE не означает соответствие текущим исходникам. Сохрани работоспособный предыдущий portable до проверки нового.
- Для дальнейшей очистки используй список известных generated-файлов, исключи профиль. Не считай папку build мусором: там ресурсы иконки. Не удаляй node_modules посреди работы ради красивого списка файлов.
- Удали реально неиспользуемый код/ресурсы после проверки ссылок и генераторов; объедини дублированные импорт/track-header реализации. Обнови README и карту структуры папок.

## Этап 1. Надёжный проект и история

1. Реализуй New/Open/Save/Save As, название проекта, dirty indicator и понятный статус autosave. Сохранение должно включать исходные медиа либо надёжную стратегию копирования/ссылок с relink. Требуется режим переносимого проекта «собрать вместе с аудио».
2. Добавь версию схемы, валидацию и миграции. Загружай восстановление до включения autosave: пустой initialProject не должен затирать существующую копию. Desktop-save делай атомарно с предыдущей резервной версией. Для веба используй подходящее хранилище медиа, а не только JSON в localStorage. Ошибка/переполнение хранилища должны быть видны.
3. Отдели project document, media registry, runtime AudioBuffers, UI selection/preferences и history. Не помещай тяжёлые PCM-данные в каждую запись Undo. Политика удаления медиа учитывает ссылки из истории.
4. Исправь drag/trim Undo: снимок до жеста, transient updates, ровно один commit при завершении, cancel на Esc. Так же группируй sliders, loop selection, rename и числовой ввод. Не записывай no-op. Добавь названия операций и корректный Redo.
5. Нормализуй selection после Undo/Redo/delete/load. Вставка клипа на отсутствующую дорожку запрещена на уровне модели. Добавь ErrorBoundary и безопасное восстановление вместо пустого экрана; не скрывай программные ошибки молча.
6. Исправь исчезновение импортированных assets после Undo другой операции. Определи единый контракт импорта и redo invalidation.
7. Проверяй конечные числа, существование id, start/offset/duration и loop.start < loop.end во всех командах, а не только в UI. При trim не смещай содержимое непреднамеренно. Если допускается тишина за границами исходника, отображай её явно.

Обязательные регрессии: импорт → монтаж → полный перезапуск; drag → Undo → Redo; trim → Undo; добавить/выбрать дорожку → Undo → вставить asset; импорт между Undo/Redo; 100 событий одного слайдера → одна запись; повреждённый проект/отсутствующее медиа/ошибка записи.

## Этап 2. Одинаковая модель звука при прослушивании и экспорте

1. Введи единое преобразование source time ↔ timeline time. У source.start duration измеряется в секундах исходного буфера: устрани двойное деление на rate, проверь offset при seek, trim/split и detune. Явно различай resampling и независимое time-stretch/pitch; не называй одно другим.
2. Заменяй/перепланируй источники по clip ID при move/trim/delete/import/Undo во время Play, сохраняя позицию транспорта. Применяй clip/input gain. Останавливай и освобождай удалённые источники/track chains. Изменения должны вступать в силу по предсказуемой политике, без продолжения удалённого материала.
3. Исправь loop: планирование по аудиочасам, актуальный snapshot, корректное выключение и изменение границ, без разрывов от stop/play через JS timeout. При необходимости используй короткое планирование вперёд; requestAnimationFrame оставь для визуализации.
4. Вычисляй общую границу контента после любых монтажных операций. Клип за прежним концом проекта виден, проигрывается и экспортируется одинаково. Добавь auto-stop по выбранной политике конца проекта/хвоста.
5. Раздели мгновенную инициализацию AudioParam и плавное обновление во время работы. Offline render с t=0 не должен содержать переход от default gain=1 в обеих dry/wet ветках.
6. Исправь peaks: все samples, включая последний, покрыты корзинами; позиции не дрейфуют по длинному файлу. Предусмотри нужные уровни детализации waveform.
7. Сделай независимые L/R peak/RMS и clip hold. Mono compatibility/correlation — отдельные индикаторы; противофаза не должна выглядеть как отсутствие сигнала. Не подписывай простую RMS-оценку как точные integrated LUFS или true peak.
8. Bypass/A-B должен быть недеструктивным: сохранять индивидуальные bypass, относиться к выбранной цепочке, согласовываться с Undo. Для реального A/B храни два набора параметров; иначе назови режим «Обойти эффекты».
9. Кешируй или сохраняй seed/IR reverb, чтобы повторный рендер неизменного проекта был воспроизводим. Убирай лишние аллокации и освобождай ресурсы.

Тесты: импульс в начале/конце; синус; тишина; L=-R; один канал; speed ×0.5/×2 и ±12 semitones; seek в середине; mute/solo; 100 loop-проходов; редактирование во время Play; null test bypass; сравнение live/offline для одинакового детерминированного графа с выравниванием начала/задержки и заданным численным допуском. Битовое совпадение требуй только от повторных детерминированных offline-рендеров в одной среде. Отличай unit/mock доказательства от настоящего Web Audio offline render и аппаратного прослушивания.

## Этап 3. Удобное перемещение по дорожкам — главный UX-приоритет

Перестрой центральную область в полноценный редактор дорожек:

- Заголовки дорожек постоянно видны слева от рядов. Имя/цвет/M/S/volume/меню доступны прямо там. Заголовки и клипы используют общую вертикальную прокрутку; по горизонтали двигается только временное содержимое.
- Видимые, удобные полосы прокрутки. Колесо — вертикаль; Shift+колесо — горизонталь; средняя кнопка — панорамирование. Сохрани нативный двухосевой trackpad. Space — Play/Pause, без конфликта с панорамированием.
- Ctrl/Cmd+колесо масштабирует относительно времени под указателем: эта точка остаётся на месте. Кнопки +/- и команды «Весь проект», «Выделение», «Выбранный клип». Настрой минимальный zoom так, чтобы длинный проект реально помещался в окно.
- Нижняя полоса обзора с viewport, который можно перемещать и масштабировать. Переходы к началу/концу и курсору; ввод времени; follow playhead с временной остановкой при ручном скролле. Маркеры/regions оставь в следующем этапе, обеспечив возможность их добавления.
- Выбор дорожки в поиске/списке показывает соответствующий ряд. Reorder за handle, изменение высоты отдельного ряда и vertical zoom, добавление/дублирование/удаление дорожек с Undo.
- Drag клипа между дорожками учитывает scroll offsets и масштаб. На краях окна — управляемый auto-scroll по обеим осям. Покажи время старта и целевую дорожку; Esc отменяет. Завершение вне ряда/окна и потеря pointer capture не оставляют зависший drag.
- Явный Snap On/Off и выбор сетки: секунды либо музыкальные доли. BPM редактируется. Рисуемая сетка совпадает с фактической привязкой. Alt временно отключает snap; единые правила move/trim/drop.
- Сохрани выделение после move и перехода на другую дорожку. Не меняй viewport при каждом Undo, если действие не относится к настройкам вида.

Приёмка: на проекте с 30 дорожками и клипами на протяжении 10 минут пользователь находит дорожку, переносит клип за край текущего окна, приближает нужное место и возвращается к полному проекту без потери контекста. Проверь обычную мышь и клавиатуру, не только тачпад.

## Этап 4. UI и базовые инструменты монтажа

Сохрани спокойную тёмную тему с умеренным акцентом, но исправь структуру:

1. Сверху — проект/сохранение и компактный transport. При 900×560 основные команды и Export остаются доступны. Никаких обязательных действий в незаметно прокручиваемой панели.
2. Слева — сворачиваемая библиотека с вкладками «Файлы / Эффекты / Пресеты», поиском и прогрессом импорта. Справа — сворачиваемый/изменяемый инспектор. Центру отдай максимальную ширину. Сохраняй размеры панелей как preferences.
3. Основной текст 12–14 px, числовые значения хорошо читаются; monospace для времени/dB. Отличимые selected/hover/focus и достаточный контраст. Интерактивные области больше визуальных тонких линий. Учитывай системный масштаб 125–150%.
4. Единая русская/английская локализация с переключением и сохранением языка. На клипе — имя медиа или заданное имя, а не только имя дорожки. Убери служебные обещания «automation-ready» и технические схемы из основного потока.
5. Реализуй multi-select (Ctrl/Cmd, Shift, рамка), групповое перемещение, copy/paste/duplicate, Delete, split, trim, nudging и fades/crossfades с Undo. Определи поведение пересекающихся клипов; не разрушай оригинальные файлы.
6. Один диспетчер горячих клавиш, подсказки и справка. Команды не срабатывают в input/select/contenteditable или модальном диалоге без явного намерения. Ctrl+S сохраняет, а не разрезает клип. Delete одного клипа создаёт одну операцию.
7. Диалоги имеют focus trap, Escape, возврат фокуса и доступные названия. Ошибки выводятся в интерфейс с конкретным действием, без зависимости от console/alert.
8. Favorites/Recent/user presets сохраняются. Quick EQ/Width должны по названию объяснять фактическое действие; если кнопка применяет целую цепочку, покажи её состав и возможность отмены.

## Этап 5. Честные эффекты, импорт и экспорт

- Объедини Sidebar import с отдельным сервисом: очередь, per-file progress/errors, отмена, retry, повторный импорт того же файла. Не позволяй ошибке AudioContext оставить вечный loading.
- Проведи проверку «каждый видимый контрол → обработка → измеримый результат». Сейчас не подключены отдельные глобальные Pan law/Width/Latency/Channel/Quality, loudness normalization, dither и часть FX-параметров. Реализуй либо явно отключи/убери их.
- Dynamic EQ, Gate, Repair и Transient не должны обещать алгоритмы, которых нет. В ближайшем выпуске допустимы честно названные упрощённые эффекты; полноценные динамические процессы требуют detector/envelope/AudioWorklet и тестов. Не добавляй фиктивные функции ради длинного списка.
- Исключи source-only Speed/Pitch из master FX либо реализуй осмысленную master-обработку. Bass mono должен действовать, если доступен.
- Export: master, selected range, loop и stems; WAV 16/24-bit и MP3 в поддерживаемых режимах, выбор sample rate, явный tail. Политика Mute/Solo/master для stems видна заранее; «все stems» не создаёт тишину из-за Solo другой дорожки.
- Peak normalization и loudness normalization — разные режимы. Для второго нужны корректное измерение и обработка цели; при отсутствии реализации режим недоступен. То же касается dither и true-peak ceiling.
- Настоящая очередь заданий вместо повтора одинакового экспорта под разными номерами. Progress/cancel, обработка ошибок, стабильный snapshot для каждого задания, блокировка противоречивых изменений. Во время busy клик по backdrop не должен просто скрыть продолжающуюся задачу без контроля.
- Имена экспортируемых файлов поддерживают кириллицу и предотвращают коллизии. Параметры, длительность, хвост и предупреждения понятны до запуска. Не показывай обещание гарантированного потолка лимитера без соответствующего DSP и теста.

## Этап 6. Производительность и выпуск

1. Виртуализируй дорожки и клипы, рисуй только видимые диапазоны/тайлы. Canvas не должен иметь ширину всего 10-минутного проекта на максимальном zoom. Переиспользуй кеши peaks и индекс track IDs.
2. EQ response рассчитывай массивом частот за один вызов на полосу; не создавай 2560 BiquadFilterNode на пересчёт кривой при изменении эффекта. Peaks, MP3 encoding и тяжёлый анализ вынеси с UI-потока с progress/cancel.
3. Задай воспроизводимые нагрузочные сценарии: 30 дорожек/10 минут и более тяжёлый сценарий на доступном компьютере. Измерь время реакции, long tasks, память до/после повторного импорта/удаления и FPS при drag/zoom. Укажи среду и фактические цифры; не выдумывай гарантии.
4. Убери allowedHosts=true, настрой production CSP и ограничения Electron navigation/windows/permissions, сохрани sandbox/contextIsolation и запрет nodeIntegration. Не расширяй доступ renderer к Node ради удобства сохранения: используй минимальный валидируемый IPC.
5. Проверь актуальные advisory, обнови зависимости совместимыми версиями, сохрани воспроизводимый lockfile. Не используй audit fix --force без разбора. Учитывай Electron runtime даже при нулевом audit --omit=dev.
6. Согласуй Node version с инструментами и CI; добавь build/lint/state/DSP/UI regression checks на PR. Windows packaging проверяй отдельно от веб-сборки.
7. Единый номер версии для package/UI/артефактов и корректные EXE metadata. В истории уже были 2.0.0, хотя текущий package — 1.2.0: устранить неоднозначность. Обнови README реальными командами и добавь release notes. Подпись только при наличии настроенного сертификата; не заявляй её без проверки.
8. Собери Windows portable в чистый каталог артефактов. Запусти именно собранный EXE: импорт, монтаж, сохранение, выход, открытие, прослушивание, WAV/MP3 export. Сохрани SHA-256 и дату сборки. Не удаляй последнюю рабочую версию до smoke новой.

## Что не включать автоматически в ближайший выпуск

Вынеси в отдельный backlog: запись с микрофона, automation lanes, buses/sends, freeze/bounce, профессиональный time-stretch, спектральное редактирование/denoise, MIDI/piano roll, VST-hosting, облачные проекты. Первые кандидаты после стабилизации — маркеры/regions, templates, удобные пользовательские пресеты и настоящая loudness-диагностика. Новые внешние сервисы, аккаунты и платные SDK не требуются для текущей задачи.

## Как работать и что выдать

Работай по этапам, с полезными промежуточными проверками. Самостоятельно решай обычные обратимые инженерные вопросы; спрашивай только при существенном выборе, который нельзя вывести из проекта. Параллельные независимые части можно делегировать, избегая одновременных правок одних файлов. Не прячь невыполненные требования за общим «готово».

Итог должен содержать:

- работающий код и актуальный portable-артефакт с точным путём;
- changelog: какие проблемы аудита исправлены, какие ограничения остаются;
- команды запуска/проверок и их фактические результаты;
- проверенные скриншоты основной рабочей области и узкого окна;
- краткую памятку по навигации и горячим клавишам;
- сведения о безопасной очистке и месте пользовательских данных;
- отдельный небольшой backlog будущих функций.

Версию считать готовой только после проверки: сохранённый проект с медиа переживает полный перезапуск; один Undo отменяет один жест; сценарий Undo дорожки не падает; монтаж соответствует звуку; нужная дорожка и время доступны удобной навигацией; доступные настройки реально действуют; экспорт предсказуем; build/lint и содержательные регрессии проходят; собранный EXE проверен. Если среда не позволяет выполнить конкретную аппаратную/платформенную проверку, укажи её точно и не выдавай за пройденную.
